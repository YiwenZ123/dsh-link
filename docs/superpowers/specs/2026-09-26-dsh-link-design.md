# DSH Link 设计

日期：2026-09-26

跨端连接器。一台 DSH 上的主 agent 把另一台 DSH 上的 agent 当作子代理来用，调用方式与本地可延续子代理相同。本地用现成的子代理界面看运行，对端用一条真实会话看同一轮运行。两端都有「设备」选项卡，用来配对和开关连接。系统可以不同，至少覆盖 macOS 与 Windows。

旧的 `dsh-bridge` 目录已不在磁盘上。本设计按当前安装的 DeepSeek Harness 新建插件，不修改它的安装目录。

## 已定决策

- 一份设计覆盖配对、委托、双端可视。实现按这个顺序切开，每段都能单独验收。
- 对端创建真实 agent 会话。对端用户只能看，不能在那条会话里发消息。
- 对齐本地可延续子代理：启动得到子会话 id，用 `send_message` 继续，打断只停当前一轮，父会话里能看到实时轨迹。子代理使用对端的模型、预设、终端、文件和工作目录。不把父会话历史发给对端。
- 局域网 mDNS 自动发现，同时允许手动填写 `主机:端口`。没有中继。
- 第一次配对核对 6 位短码。之后记住设备 id 和公钥，重连不再要短码。
- 本地不跑这条委托的模型。本地子会话是镜像，用来接现成的子代理界面。

## 架构

两端安装同一个插件，没有永久的主从角色。一次委托才有父端和对端。

插件有宿主半和浏览器半。宿主半挂进当前 web profile 的 cordis patch。浏览器半声明 `dsh.client`，由现有的 client-modules 加载。「设备」选项卡占用 `sidebar.panellist` 和 `main`。子代理目录、转录和「正在运行」仍用现成的子代理界面，不另做一套轨迹视图。

宿主半三块：

| 块 | 职责 |
|---|---|
| 设备目录 | 本机身份、已记住的对端、连接开关 |
| 载波 | 自己的监听端口、mDNS、手动拨号、配对后的鉴权连接 |
| 委托 | 父端建镜像子会话；对端建真实 agent 会话并推送事件 |

载波不走浏览器那条带 cookie 的通道，也不改 `dsh web` 的绑定地址。DeepSeek Harness 拒绝把网页服务绑到 `0.0.0.0`，本插件的监听端口是另一套套接字。

## 身份与配对

### 本机身份

第一次启动时生成：

- `deviceId`：UUID
- 显示名：默认识别到的主机名，可在选项卡里修改
- Ed25519 密钥对

这些字段和下面的监听设置一起放在 `~/.dsh/link/identity.json`。已配对设备放在 `~/.dsh/link/peers/`。重启后仍在。删掉 `~/.dsh/link/` 等于换了一台新设备，旧对端必须重新配对。私钥只放在这份身份文件里，不进入本仓库。

默认监听端口是 `48721`。端口被占用时改绑下一个可用端口，并把实际端口写回身份记录。mDNS 和手动地址都使用实际端口。

### 发现

监听开启且「允许被局域网发现」打开时，发布 DNS-SD 服务 `_dsh-link._tcp`。TXT 含 `deviceId`、显示名、协议版本 `1`。端口放在 SRV 记录里。

浏览同一个服务类型，把尚未配对的设备显示为「附近」。mDNS 只负责局域网。跨网段、Tailscale 和端口转发使用手动地址，格式为 `主机:端口`。主机可以是 IP、主机名或 Tailscale 名。

Windows 上若多播或入站被系统拦住，附近列表可以为空。手动地址仍然可用。

### 短码

未配对的连接只允许做配对，不能发委托。

1. 发起方拨号并发送 `hello`（协议版本、deviceId、显示名、长期公钥、本次临时公钥）。
2. 接受方回复自己的 `hello`。
3. 规范 JSON 指键名按字母序、中间没有空白的 UTF-8。两边把发起方 `hello` 的规范 JSON、一个换行、接受方 `hello` 的规范 JSON 连起来，取 SHA-256 的前 3 字节作为大端整数，再对 1000000 取模，左侧补零成 6 位短码。
4. 发起方屏幕显示短码。接受方必须输入在另一台机器上看到的短码。
5. 接受方先核对自己算出的短码。不一致就拒绝，两边都不保存。
6. 一致后，接受方发送确认。发起方再核对自己算出的短码。一致后两边保存对方的 deviceId、显示名、长期公钥和这次的地址。

同一配对请求连续输错 5 次后，1 分钟内拒绝这次请求。锁定期结束才能再试。短码输错不写入已配对列表。

拨号的一方是发起方，监听的一方是接受方。两边同时拨号时，保留 deviceId 字典序较小的一方发出的那条连接，另一条关闭。已记住的设备重连时做挑战应答，证明持有当初保存的私钥。deviceId 对上但公钥不一致：拒绝连接，选项卡显示密钥不符，不更换已保存的公钥。协议版本不是 `1`：状态记为失败，原因是版本不一致，委托接口关闭。第一次配对时不写入设备记录。已经配对的设备保留记录，只是这次连不上。

取消配对会删除该设备记录和公钥。下次必须重新短码。

### 已记住的设备

每台已配对设备保存：`deviceId`、显示名、公钥、上次主机、上次端口、开关、配对时间。

开关关掉时关闭套接字，并拒绝指向这台设备的新委托。开关打开时先拨上次的地址。已经连着时，mDNS 报来的新地址只更新记录，不拆掉当前连接。当前没有连接而开关仍开着时，用新地址拨号。掉线后若开关仍开着，按 1 秒、2 秒、4 秒退避重拨，间隔最高 15 秒，直到连上或用户关掉开关。这个重拨和下面「当前这一轮只等 15 秒」是两件事：轮次不再恢复，连接继续尝试。

可以同时记住多台设备，每台单独开关。委托必须点名一台当前已连接的设备，不自动挑选。

### 选项卡

选项卡标题为「设备」，内容为四块：

- 本机：显示名、deviceId 的前 8 位、实际端口、「允许被局域网发现」开关
- 已记住的设备：开关、状态、上次地址、取消配对
- 附近尚未配对的设备：配对
- 手动地址：输入框，以及「连接并配对」

状态只有：未配对、已配对但关闭、连接中、已连接、重新连接中、失败。失败原因只使用这三句：地址不可达、密钥不符、版本不一致。拨号超时 8 秒，超时记为地址不可达。

### 载波消息

一条 WebSocket 文本帧是一条 JSON 对象。单帧上限 1 MiB。更大的委托事件拆成 `delegate.event.part`，接收方按委托 id 和分片序号拼回，再写入会话。拼好的单条事件上限 32 MiB，超过则这条委托以错误结束，诊断为「事件过大」，已写入的镜像事件保留。

配对完成前允许的消息：`hello`、`pair.confirm`。配对完成后、鉴权完成前允许的消息：`auth.challenge`、`auth.proof`。鉴权完成后才允许 `delegate.*` 和 `resume`。

`hello` 含协议版本、deviceId、显示名、长期公钥、临时公钥。`pair.confirm` 含接受方输入的 6 位短码。`auth.challenge` 含 32 字节随机数。`auth.proof` 是对这个随机数的 Ed25519 签名。父端生成 `delegationId`。`delegate.start` 含 delegationId、标签、任务文本、父会话 id。`delegate.started` 含 delegationId 和对端会话 id。`delegate.ready` 含 delegationId，表示父端目录已经写好，对端可以开始模型。`delegate.abort` 含 delegationId，表示父端目录没写好，对端丢弃刚建的会话。`delegate.event` 含 delegationId、序号和一条会话事件。`delegate.event.part` 含 delegationId、序号、分片序号、分片总数和分片正文。`delegate.followup` 与 `delegate.cancel` 含 delegationId。`resume` 含 delegationId 和已应用的最后序号。`delegate.settled` 含 delegationId、终止原因和可空的最终助手文本。

## 委托与镜像

### 模型看到的工具

工具名为 `link_subagent`，避免和现成的 `subagent` 撞名。参数与本地可延续子代理相同，并多一个 `deviceId`。`deviceId` 的可选取值是调用当时已连接的已配对设备。没有已连接设备时，工具调用返回错误「没有已连接的设备」，不建会话。

后台行为与本地可延续子代理相同：

- 启动成功的工具结果是 `started subagent <本地子会话 id>`
- 后续消息使用现成的 `send_message`，目标是这个本地子会话 id
- 打断只结束当前一轮，子会话保留
- 一轮结束由结算通知告诉父模型，通知里带最终助手文本
- 不把父会话历史发给对端

现成的 `send_message` 若只投递到本机 Agent 收件箱，插件在投递到 link 子会话时改为转发给对端，不在本地启动模型。

### 建立

父端先确认目标设备已连接。未连接则工具返回错误「设备未连接」，父会话不出现子代理条目。

对端先创建真实 agent 会话。创建失败则父端不写 `subagent/catalog`，工具返回错误。对端会话使用对端自己的模型、预设和工具，工作目录是对端自己的工作区。不把父端路径映射到对端。路径和 shell 的差异是对端工具的普通结果。

对端会话进入对端的普通会话列表。标题使用委托标签，并写明来自哪台设备。宿主拒绝这条会话上的用户消息，不只是隐藏输入框。拒绝原因对坐在对端的人显示为这条会话由那台设备驱动。

对端创建成功后先把事件暂存，不启动模型。父端创建 `origin: subagent` 的子会话，设置父会话指针，并向父会话追加 `subagent/catalog`（模式 `continuable`，带标签）。本地子会话 id 与对端会话 id 不同。父端保存本地子会话 id、对端会话 id、delegationId、对端 deviceId、父会话 id、已应用序号和阶段。对端保存 delegationId、对端会话 id、父端 deviceId、已发送序号和阶段。目录写好后父端发送 `delegate.ready`，对端才启动模型，并先发出暂存的事件。

若对端会话已经建好，但父端目录写入失败，父端发送 `delegate.abort`，对端丢弃刚建的会话，工具返回错误，父会话里不留下子代理条目。

### 事件镜像

对端把这些会话事件按发生顺序推给父端：`turn/start`、助手消息、`tool/call`、`tool/result`、`turn/end`。每条带本委托内从 1 递增的序号。父端只把大于已应用序号的事件写入本地子会话。本地子会话不执行工具，也不调用模型。打开本地子会话看到的轨迹就是对端正在做的事。

同一子代理同时只有一轮在跑。`delegate.start` 里的任务文本先于任何后续消息。后到的 `send_message` 进入对端的收件顺序，等当前一轮结束再开始。`delegate.ready` 之前到达的后续消息也排在任务文本之后。

对端一轮进行期间，父端保持该子会话驻留，并维持一个不调用模型的 Agent 壳，使现成目录的活动状态为「正在运行」。一轮结束，壳变为未运行，会话保留。下一次 `send_message` 再让对端开始新的一轮，壳回到运行中。

同一对端可以同时存在多条委托。每条委托有自己的一对会话和自己的序号，事件不得串线。

### 打断

父端打断发送 `delegate.cancel`。对端取消当前一轮，会话保留。父端镜像写入这一轮的结束，结算原因是中断。之后的 `send_message` 仍可开始新的一轮。

## 断线与失败

会话一旦建立就保留。连接问题只结束当前一轮，不删除两边的会话。

载波发现套接字关闭时开始 15 秒等待。等待期间：

- 对端把新事件按序号暂存
- 父端目录仍显示正在运行
- 选项卡状态为重新连接中

重连并完成鉴权后，父端发送 `resume`，带上已应用的最后序号。对端只补发更大的序号。重复序号丢弃。15 秒内接回，这一轮继续。

超过 15 秒，两边都结束当前一轮，结算原因为中断，诊断为「连接已断开」。子会话还在。再次连上后，`send_message` 可以开始新的一轮。

下面几种情况不等待 15 秒，立刻中断当前一轮：

- 关掉这台设备的开关
- 取消配对
- 密钥不符
- 协议版本不一致

关掉开关后，对应关系还在。重新打开连接并通过鉴权后，可以继续 `send_message`。取消配对后对应关系作废，再发消息返回错误「设备未配对」。两边已有的转录仍可打开。

未连接时的 `send_message` 直接失败，返回「设备未连接」，不在父端排队。若打断发生时链路已断，父端记下这次打断；若 15 秒内重连且这一轮还在，就把 `delegate.cancel` 送出。若等待已经超时并完成中断，这次打断视为已经完成。

对端模型这一轮失败时，父端结算原因为错误，诊断是一句说明，不含密钥、令牌或环境变量。工具失败写在轨迹的工具结果里，由对端模型处理，不当成链路失败。

只把父会话翻到别的页面时，对端继续跑。结束当前一轮的条件只包括：明确打断、关掉开关、取消配对、密钥或版本失败、等待满 15 秒、对端模型这一轮失败、事件超过 32 MiB。套接字仅仅断开时不在此列，要等满 15 秒。

## 数据流

父端启动：

1. `link_subagent` 点名一台已连接设备。
2. 父端发送 `delegate.start`（delegationId、标签、任务文本、父会话 id）。
3. 对端创建真实会话并回复 `delegate.started`（delegationId、对端会话 id）。
4. 父端创建镜像子会话并写入目录，发送 `delegate.ready`，回复工具结果 `started subagent <本地子会话 id>`。
5. 对端收到 `delegate.ready` 后启动模型，连续发送 `delegate.event`。
6. 父端按序号写入镜像。
7. 对端发送 `delegate.settled`。父端结束 Agent 壳的运行状态，并向父模型发出结算通知。

第 2 段实现时，测试探针写好就发送 `delegate.ready`。第 3 段起，改为目录写好才发送。

继续一轮时，`send_message` 变成 `delegate.followup`。打断变成 `delegate.cancel`。重连补发使用 `resume`。

## 实现顺序

三段都在本仓库里完成，后一段依赖前一段的记录格式。

1. 配对与连接。交付身份、mDNS、手动地址、短码、设备目录、选项卡和开关。这一段不能发起委托。
2. 委托。交付 `link_subagent`、`send_message` 转发、对端真实会话、事件序号、打断和本文的断线规则。这一段把事件写进测试探针。探针里的记录和下一阶段写入镜像子会话的记录是同一格式。
3. 双端可视。把探针换成父端的镜像子会话：写入 `subagent/catalog` 和镜像事件，现成子代理界面能打开并在运行时显示正在运行。对端会话出现在普通会话列表，宿主拒绝用户消息。

## 验收

第 1 段结束时，本机双进程清单里只要求配对、重启重连、错误短码和开关这几条通过。第 2 段结束时，协议测试全部通过，双进程里能用探针看到委托事件。第 3 段结束时，本机双进程清单全部通过。跨系统手测在第 3 段之后做。

### 协议测试

用假时钟和内存中的两端协议对象，不启动完整 DSH：

- 短码一致才写入配对；两边抄本不一致时两边都不保存
- 连续 5 次错误后，1 分钟内拒绝，锁定期过后可以再试
- 公钥变化被拒绝，已保存公钥不变
- 序号补发不重复写入；分片能拼回一条事件
- 套接字在 15 秒内恢复时这一轮继续；假时钟跨过 15 秒时这一轮中断，诊断为「连接已断开」
- 关开关和取消配对不进入 15 秒等待
- 超过 32 MiB 的事件以「事件过大」结束，已写入部分保留

### 本机双进程

在同一台 macOS 上启动两个 DSH 进程，使用不同的数据目录和端口，只用手动地址：

- 短码配对成功，重启两个进程后打开开关可以连上，不再要短码
- 错误短码不出现在已配对列表
- 父端调用 `link_subagent` 后，对端会话列表出现一条新会话
- 向对端那条会话发送用户消息被宿主拒绝
- 父端打开子会话能看到对端的工具调用和结果，目录在运行时显示正在运行
- `send_message` 让同一对端会话再跑一轮
- 打断后子会话还在，再发 `send_message` 可以开始新的一轮
- 父会话历史不出现在对端会话的用户消息里
- 设备未连接时调用工具，父会话不新增子代理条目
- 对同一设备并发两条委托，事件不错配
- 关掉开关会立刻结束当前一轮；重新打开后 `send_message` 可以继续
- 取消配对后 `send_message` 失败，两边旧转录仍能打开

### 跨系统手测

不放进自动测试。清单至少包括一对 macOS 与 Windows：

- 局域网里能在「附近」看到对方；若 Windows 看不到，手动地址仍能配对
- 第一次运行时若系统询问入站端口，允许后手动地址或发现可以连上
- 对端执行的终端是对端系统的终端，轨迹里的路径是对端路径
- 父端子代理目录和对端会话列表都能看到同一次运行

## 非目标

- 对端用户在被驱动的会话里发消息或接手
- 公网中继、自动打洞
- 未点名时自动选择一台设备
- 把父端工作目录映射到对端
- 把父会话全文注入对端
- 修改 DeepSeek Harness 的安装文件
- 复用已经不在磁盘上的 `dsh-bridge` 代码
